Lifecycle of Love Platform

Dating and being in a relationship are two completely different jobs. We build both, on one continuous, verified account.

  • The Dating Resume A verified single profile built on real signal — relationship history, intentions, and confirmed status — replacing guesswork with data-driven insight.
  • The Commitment Lock When two users match and both accept relationship status, the app instantly transitions them into Couples Mode and removes them from the singles market.
  • The Relationship Pulse A private, gamified fitness tracker for the heart — daily check-ins and a shared harmony score that help couples stay close, together.

Built for Privacy & Scale

Trust is the entire product. Every architectural decision is made to protect the two things people hand us: their history, and their honesty.

  • State-Driven Backend A relational PostgreSQL core cleanly models each user's conditional state — Single or Coupled — so the product logic and the data model never drift apart.
  • Airtight Privacy Strict data siloing keeps sensitive material — relationship history, private couple logs — encrypted at rest and controlled entirely by the people it belongs to.
  • Double-Blind Scoring Daily relationship ratings stay sealed until both partners have submitted theirs, so no one can see a partner's score first and react to it instead of answering honestly.
-- Vow Database Schema
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email VARCHAR(255) UNIQUE,
  status VARCHAR(20) CHECK (status IN ('single', 'coupled')),
  vouch_rating INTEGER DEFAULT 100
);

CREATE TABLE relationships (
  id UUID PRIMARY KEY,
  user_1_id UUID REFERENCES users(id),
  user_2_id UUID REFERENCES users(id),
  created_at TIMESTAMP DEFAULT NOW(),
  harmony_score NUMERIC(5,2)
);
